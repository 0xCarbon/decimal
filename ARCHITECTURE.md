# Architecture

How the repository is laid out, what may import what, and how the library
is verified. The [design rationale](docs/rationale.md) explains why the
library is built this way; the [semantics reference](docs/reference/semantics.md)
states what it promises.

## Layout

One Go module, `github.com/0xCarbon/decimal`, pure Go 1.27.1,
`CGO_ENABLED=0` everywhere. The single public package `decimal` lives at
the module root. The Makefile and CI build with `GOEXPERIMENT=simd` by
default; a plain `go build` selects the scalar files, and the scalar
profile (`GOEXPERIMENT=`) is built and tested alike.

## Import rules

- The root package imports the standard library only. `make checkdeps`
  enforces it in every build configuration, and the library `go.mod` has
  no `require` line.
- `tools/` and `benchmarks/` belong to the library module, so they are
  standard-library-only too. The incumbent harness in
  `benchmarks/incumbents` is its own module and is the only place
  third-party decimal libraries appear; nothing imports it.
- `tools/` and `benchmarks/` import the root package; the root never
  imports them.
- No `unsafe`, assembly, object files or direct `simd/archsimd` imports.
  Byte kernels are SWAR on 64-bit words; the portable `simd` span kernel is
  an unexported `goexperiment.simd` file used only for `[]byte` input, with
  a scalar twin. The compiler owns ISA dispatch and emulation.

## Verification

- **Independent oracles.** Results are checked against `math/big`,
  `strconv`, `encoding/json` or hand-derived vectors, never against the
  code under test. `tools/oracle` runs a seeded rational differential of
  every rounding operation in every mode, plus property laws with negative
  controls that must catch deliberately defective operations.
- **Fast paths never own semantics.** An optimized path returns only when
  its result is provably what the general path returns, and otherwise
  defers to it. Differential tests pin each fast path to the general path
  over randomized and boundary inputs. A budgeted call takes a fast path
  only when its budget admits a derived bound of the general charge for
  that shape (the constants in `cost.go`) or the general path's own pricing
  of the call, so a budget never changes a result or a refusal.
- **Conformance corpus.** `make conformance` downloads the General Decimal
  Arithmetic decTest suites, verifies their hashes, classifies every case
  through `testdata/dectest/manifest.json` (adopted, excluded with a
  reason, or re-derived with provenance) and runs every adopted case.
  Any drift between corpus, rules and manifest fails.
- **Fuzzing.** Every fuzz target's committed corpus runs on each
  `go test`; `make fuzz-smoke` fuzzes each target briefly, and crashers
  are promoted to committed seeds with a named regression test.
- **Correct-rounding claims.** Each claim in the documentation cites
  [docs/reference/correct-rounding.md](docs/reference/correct-rounding.md),
  whose rows name the checker test and oracle cases; a test keeps the
  claims and the table in step.
- **Build profiles and platforms.** CI runs the full suite in both
  profiles on linux/amd64, linux/arm64, macOS arm64, windows/amd64 and
  linux/386, and on js/wasm under Node. `testdata/portable-results.sha256`
  pins a digest of results that must be bit-identical everywhere.
- **Benchmarks.** Every timed row first checks its results against an
  oracle, so a fast but wrong implementation fails before it is measured.
  Performance changes are decided with interleaved A/B runs compared with
  `tools/benchcmp`.

## Resources and concurrency

Allocation, copying and growth are properties of the representation: an
operation on inline operands (coefficients below 2^128) with an inline
result allocates nothing, and allocation classes for larger results are
pinned by tests in `benchmarks/`. Every operation whose work depends on
input size has a budgeted form, and budgets refuse before allocating.
Values are immutable and there is no global or goroutine-local state that
affects a result (`tools/checkstate`), so values are safe to share between
goroutines; concurrent-use tests run in the library package.
